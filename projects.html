PROJECT_001

Debian Home Server

Repurposed an older laptop into a Linux-based home server capable of providing network services, secure file sharing, remote access and web hosting.

OBJECTIVE

Build a practical Linux server while learning system administration, networking and service management.

PLATFORM

Debian Linux running on an ASUS K53S laptop with Intel Core i5 processor, 4 GB RAM and internal HDD.

SERVICES

AdGuard Home, Samba, Tailscale, UFW and Nginx.

RESULT

Functional home server supporting networking, file services, remote access and web hosting.

01 — Installation

Installed Debian Linux on the repurposed laptop and prepared the system for self-hosted server workloads.

02 — Networking

Configured a static IPv4 address and integrated the server into the home network for reliable service access.

03 — Services

Deployed AdGuard Home for DNS/DHCP, Samba for file sharing, Tailscale for remote access and Nginx for web hosting.

04 — Security

Configured UFW with a default-deny inbound policy and allowed services only where network access was required.

DEBIAN LINUX SERVER NETWORKING
PROJECT_002

Network DNS & DHCP Security

Configured AdGuard Home as a network-wide DNS and DHCP service while troubleshooting DNS, IPv4, IPv6 and router configuration issues.

OBJECTIVE

Centralize DNS and DHCP services while building practical experience with network-wide DNS management.

DNS SERVER

AdGuard Home running on the Debian server and providing DNS resolution for the local network.

DHCP

DHCP was moved from the router to AdGuard Home so clients could receive the intended DNS configuration.

SECURITY

DNS access is restricted to the local network, preventing the resolver from being exposed publicly.

01 — Static Server Address

Configured the Debian server with a stable internal IPv4 address for reliable DNS and DHCP service delivery.

02 — DNS

Configured AdGuard Home as the network DNS service and verified DNS resolution from connected clients.

03 — DHCP

Disabled the router DHCP service and configured AdGuard Home to provide DHCP addresses and the intended DNS server.

04 — IPv6 Investigation

Investigated IPv6 as a potential DNS bypass path and disabled router IPv6 Internet connectivity to keep DNS control within the lab network.

ADGUARD DNS DHCP IPV4 IPV6
PROJECT_003

Secure Samba File Server

Built a Linux-based file server with authenticated Samba access and network-restricted firewall rules.

OBJECTIVE

Provide secure file sharing between Windows and Linux systems on the home network.

AUTHENTICATION

Created a dedicated Linux/Samba account for file server access.

ACCESS CONTROL

Samba services were restricted by UFW to the internal network.

REMOTE ACCESS

Remote file access is performed through the private Tailscale network rather than exposing SMB publicly.

01 — Storage

Created a dedicated server storage location for shared files and assigned ownership to the file-server account.

02 — Samba

Installed and configured Samba with an authenticated Files share for controlled network file access.

03 — Testing

Verified the Samba share locally and from Windows, confirming authenticated access and file operations.

04 — Firewall

Restricted SMB-related ports to the home network with UFW and kept SMB inaccessible from public networks.

SAMBA SMB LINUX UFW
PROJECT_004

Tailscale Remote Access

Implemented secure remote access to the Debian server after identifying that the home Internet connection was behind upstream NAT.

PROBLEM

The router received a private WAN address while the connection had a separate public address.

IMPLICATION

Traditional inbound port forwarding was not a suitable solution for remote access.

SOLUTION

Used Tailscale to establish private connectivity between trusted devices.

SECURITY

SMB remains unexposed to the public Internet.

01 — Network Investigation

Compared the router WAN address with the observed public address and identified upstream NAT as the connectivity constraint.

02 — Tailscale Installation

Installed and authenticated Tailscale on the Debian server and Windows client to establish private connectivity.

03 — Connectivity Test

Verified connectivity using the server's Tailscale address from the remote Windows client.

04 — SMB Test

Successfully accessed the Samba share remotely through the private Tailscale network without exposing SMB publicly.

TAILSCALE CGNAT VPN SMB
PROJECT_005

Linux Firewall

Configured UFW as a host firewall and created rules based on the intended network exposure of each service.

DEFAULT POLICY

Incoming connections are denied by default while outgoing connections are allowed.

LAN SERVICES

Samba, DNS and the local portfolio web service are restricted to the home network.

REMOTE NETWORK

Tailscale interface traffic is permitted for private remote access.

VERIFICATION

Tested both local and remote access after enabling the firewall.

01 — Install

Installed UFW and reviewed the server's existing listening services before applying firewall rules.

02 — Default Rules

Configured a deny-by-default inbound policy while allowing outbound traffic required by the server.

03 — Service Rules

Added service-specific rules for SSH, DNS, DHCP, Samba, HTTP and the portfolio web service with network restrictions.

04 — Validation

Verified that Tailscale and Samba continued to function correctly after the firewall rules were applied.

UFW FIREWALL LINUX ACCESS CONTROL
